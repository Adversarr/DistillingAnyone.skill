# Rubric

Freeze **after** analyze and problems, **before** drafting SomeSkill.

## Lock

For each brief, write scratch `rubrics/<same-stem>.md` with HIT / MISS / WRONG items:

- **outcome** — the checkable result the human demanded or accepted
- **insisted** — methods from `coverage.md` that apply to this problem

A HIT item is observable in the tester’s work product or process note. Adjectives (“be careful”) are not items.

## Freeze

After this file is written, the **rubric** does not change for the rest of the run unless the user cancels and re-freezes.

Testers never see these files. They stay in scratch.

## Done

Every brief has a rubric. Item count is finite. A stranger could grade HIT / MISS / WRONG from the tester output alone. SomeSkill has not been drafted yet (create) or has not been patched for this run yet (evolve).
